# 审查规范 - 六维质量审查指南

## 审查维度

### 1. High-point（爽点密度）
检查本章爽点设计与密度。

**检查点**：
- 是否有明确的爽点设计
- 爽点密度是否适中（不稀疏也不过密）
- 爽点与情节的衔接是否自然

**问题示例**：
- "这章太平了，没有任何爽点"
- "爽点来得太突然，没有铺垫"

### 2. Consistency（设定一致性）
检查世界观、力量体系、地理等设定的一致性。

**检查点**：
- 角色能力是否与当前境界匹配
- 地点描述是否前后一致
- 时间线是否连贯
- 物品/货币是否符合已建立规则

**问题示例**：
- "前文说主角是炼气三层，这里却能打败筑基期"
- "前天还在青云镇，今天就到了百里外，没有交代"

### 3. Pacing（节奏）
检查 Strand 分布和节奏断档。

**检查点**：
- Quest/Fire/Constellation 比例是否合理
- 是否有节奏断档（某种 Strand 太久没出现）
- 高潮和铺垫是否交替

**问题示例**：
- "连续5章都是主线，没有感情戏"
- "这章全是日常，没有推进剧情"

### 4. OOC（角色一致性）
检查角色行为是否偏离人设。

**检查点**：
- 对话风格是否符合角色特征
- 行为是否与性格一致
- 角色知识边界是否合理
- 决策是否有合理动机

**问题示例**：
- "萧炎平时冷酷，这里突然话很多，不像他"
- "他刚被背叛，却立刻相信了对方的话"

### 5. Continuity（叙事连贯）
检查场景转换和情绪衔接。

**检查点**：
- 上章钩子是否有回应
- 场景转换是否有过渡
- 情绪弧是否连续
- 逻辑链条是否完整

**问题示例**：
- "上章结尾的悬念这章没解决"
- "上一秒还在悲伤，下一秒就笑了，没有过渡"

### 6. Reader-pull（追读力）
检查钩子强度和期待管理。

**检查点**：
- 章末钩子是否有效
- 是否有未完成的悬念积累
- 读者期待是否被管理

**问题示例**：
- "章末太平淡，没有留悬念"
- "悬念太多，都没有解决"

## AI 味检查

### 词汇层
| 问题 | 示例 |
|------|------|
| 高频AI词汇 | "缓缓""淡淡""微微" |
| 神态模板 | "眸中闪过""瞳孔微缩""嘴角勾起" |

### 句式层
| 问题 | 示例 |
|------|------|
| 四段闭环 | 起因→经过→结果→感悟 |
| 同构句 | 连续3句以上主谓宾结构一致 |
| 总结句 | 每段都以"他明白了"收尾 |

### 叙事层
| 问题 | 示例 |
|------|------|
| 反讽提示 | "他不知道的是..." |
| 安全着陆 | 冲突完美解决，无遗留 |
| 展示+解释 | 动作后紧跟解释 |

### 情感层
| 问题 | 示例 |
|------|------|
| 情绪标签 | "他感到愤怒" |
| 即时切换 | 上句愤怒，下句平静 |
| 统一模板 | 全员"瞳孔微缩" |

### 对话层
| 问题 | 示例 |
|------|------|
| 信息宣讲 | 解释背景而非推进冲突 |
| 书面语 | 全员正式，无口语特征 |
| 解释叙述 | "他这么说是因为..." |

## 问题报告格式

```json
{
  "issues": [
    {
      "severity": "critical | high | medium | low",
      "category": "continuity | setting | character | timeline | ai_flavor | logic",
      "location": "第N段 或 具体引用",
      "description": "问题描述",
      "evidence": "原文引用 vs 数据记录",
      "fix_hint": "修复方向",
      "blocking": true
    }
  ]
}
```

### severity 等级
- **critical**：事实矛盾，必须修复
- **high**：严重影响阅读
- **medium**：影响体验，建议修复
- **low**：细节问题，可以忽略

### blocking 字段
- `true`：阻断性问题，必须先修复才能继续
- `false`：建议性修改
