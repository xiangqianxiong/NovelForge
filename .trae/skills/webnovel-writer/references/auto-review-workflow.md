# 自动审核评分工作流

## 概述

本文档定义了章节完成后的自动审核评分流程，确保每个章节都经过严格的质量检查，不合格章节将自动打回优化。

## 自动审核流程

```
章节写作完成
    ↓
[Phase 1: 自动评分]
    ↓
检查分数是否 >= 75
    ↓
    ├─ 是 ─→ [Phase 2: 提交确认]
    │              ↓
    │         保存到正式目录
    │         更新状态
    │         完成 ✓
    │
    └─ 否 ─→ [Phase 3: 打回优化]
                   ↓
              通知用户问题
              提供修改建议
              等待重新提交
```

## Phase 1: 自动评分

### 评分标准

章节评分采用百分制，包含以下维度：

| 维度 | 权重 | 说明 | 通过阈值 |
|------|------|------|----------|
| **High-point** | 20% | 爽点密度与质量 | >= 15/20 |
| **Consistency** | 20% | 设定一致性 | >= 15/20 |
| **Pacing** | 15% | Strand 节奏比例 | >= 11/15 |
| **OOC** | 15% | 人物性格一致性 | >= 12/15 |
| **Continuity** | 15% | 叙事连贯性 | >= 11/15 |
| **Reader-pull** | 15% | 钩子强度 | >= 11/15 |

### 评分等级

| 等级 | 分数范围 | 处理方式 |
|------|----------|----------|
| **优秀** | 90-100 | ✅ 直接通过，推荐精品 |
| **良好** | 75-89 | ✅ 通过，可小幅优化 |
| **合格** | 60-74 | ⚠️ 通过，需注意问题 |
| **不合格** | <60 | ❌ 打回优化 |

### 通过条件

章节必须同时满足以下条件才能通过：

1. **总分 >= 75**
2. **无 critical 级别问题**
3. **高优先级问题 <= 3个**
4. **AI味检测通过**
5. **字数在目标范围内**

## Phase 2: 提交确认

### 通过后的处理

1. **保存章节**
   - 移动到正式正文目录
   - 更新章节索引

2. **更新状态**
   ```json
   {
     "chapter": 51,
     "score": 82,
     "status": "published",
     "review_timestamp": "2024-01-15T10:30:00Z"
   }
   ```

3. **记录评估**
   - 保存详细评估报告到 `.webnovel/evaluations/`
   - 更新项目统计

## Phase 3: 打回优化

### 不通过条件

以下任一条件触发打回：

1. **总分 < 75**
2. **存在 >= 1 个 critical 级别问题**
3. **高优先级问题 > 3 个**
4. **AI味检测失败**
5. **字数偏差 > 30%**

### 打回通知格式

```json
{
  "chapter": 51,
  "status": "rejected",
  "score": 68,
  "threshold": 75,
  "issues_summary": {
    "critical": 0,
    "high": 4,
    "medium": 2,
    "low": 1
  },
  "blocking_issues": [
    {
      "severity": "high",
      "category": "consistency",
      "description": "主角境界设定与前文冲突",
      "fix_hint": "将筑基巅峰改为筑基后期"
    }
  ],
  "recommendations": [
    "增加爽点描写",
    "优化章节结尾钩子"
  ],
  "can_resubmit": true
}
```

### 打回后的用户提示

```
⚠️ 章节审核未通过

📊 综合评分：68/75 (不合格)

❌ 关键问题：
1. [HIGH] 设定一致性 - 主角境界与前文冲突
2. [HIGH] 爽点密度 - 缺少主要爽点
3. [MEDIUM] AI味检测 - 部分表达过于模板化

💡 修改建议：
• 将"筑基巅峰"改为"筑基后期"
• 添加主角反杀boss的爽点场景
• 删除"缓缓""淡淡"等AI味词汇

✅ 修复后可重新提交审核
```

## 自动审核执行流程

### Step 1: 触发审核

章节写作完成后自动触发，无需用户手动调用。

### Step 2: 执行评分

1. **加载章节内容**
   - 读取正文文件
   - 加载项目设定

2. **执行多维度检查**
   - 六维质量审查
   - AI味检测
   - 一致性检查
   - 字数统计

3. **计算综合分数**
   - 加权平均
   - 问题扣分
   - 最终评分

### Step 3: 判定结果

根据评分和通过条件判定：

```
IF score >= 75 AND no_critical AND high_priority <= 3:
    → 提交通过
ELSE:
    → 打回优化
```

### Step 4: 执行动作

**通过时：**
1. 保存章节到正式目录
2. 更新 state.json
3. 生成评估报告
4. 通知用户

**打回时：**
1. 生成详细问题清单
2. 提供修改建议
3. 标记章节为待优化状态
4. 等待用户修复后重新提交

## 特殊情况处理

### 首次写作

前3章采用宽松标准：
- 通过阈值降低到 65
- 重点关注结构和钩子
- 鼓励创新

### 批量写作

批量写作采用严格标准：
- 每章都必须通过审核
- 任何章节失败暂停整个批次
- 提供批量修复建议

### 紧急提交

允许跳过审核（需用户确认）：
- 标记为"草稿"状态
- 后续补充审核
- 不影响整体评分

```json
{
  "auto_review": {

    "threshold": 75,
    "strict_mode": false,
    "first_chapter_lenient": true

  "blocking_conditions": {
```

可根据题材调整权重：

| 题材 | High-point | Consistency | Pacing | OOC | Continuity | Reader-pull |
|------|------------|-------------|--------|-----|------------|-------------|
| 玄幻修仙 | 25% | 20% | 15% | 10% | 15% | 15% |
| 都市异能 | 20% | 15% | 15% | 20% | 15% | 15% |
| 言情 | 15% | 15% | 15% | 25% | 15% | 15% |

## 与现有系统集成

### 与 webnovel-write 集成

```
章节写作完成
    ↓
自动触发审核
    ↓
评分 + 判定
    ↓
通过 ─→ 提交
失败 ─→ 打回优化
```

### 与 webnovel-review 集成

自动审核复用 `webnovel-review` 的检查逻辑：
- 六维质量审查
- AI味检测
- 设定一致性检查

### 与 grading-standards.md 集成

使用统一样式评分：
- 评分维度
- 等级定义
- 通过标准

## 最佳实践

### 快速修复建议

针对常见问题提供一键修复：

| 问题类型 | 快速修复 |
|---------|---------|
| AI味过重 | 删除感悟句、替换AI词汇 |
| 节奏平淡 | 增加冲突、加快节奏 |
| 钩子不足 | 添加悬念、反转 |
| 设定冲突 | 调用设定修复工具 |

### 增量优化

不要一次性大改，采用增量优化：

1. 修复 critical 和 high 问题
2. 重新评分
3. 迭代优化 medium 问题
4. 最终打磨 low 问题

### 保持创作节奏

在质量和效率间平衡：
- 优先保证核心爽点
- 控制修改时间
- 避免过度完美主义
