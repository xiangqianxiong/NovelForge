# Grading 评估标准

本文档定义了网文创作系统中每个 Agent 的输出质量和评估标准。

## 评估框架

### 评分等级

| 等级 | 分数范围 | 说明 |
|------|----------|------|
| 优秀 | 90-100 | 超出预期，质量极高 |
| 良好 | 75-89 | 符合预期，质量良好 |
| 合格 | 60-74 | 基本符合，有小问题 |
| 不合格 | <60 | 未达到基本要求 |

### 评估维度

1. **准确性** - 信息和数据的正确性
2. **完整性** - 覆盖所有必要内容
3. **一致性** - 与项目设定保持一致
4. **实用性** - 输出对写作有实际帮助
5. **可读性** - 语言清晰，格式规范

## Agent 评估标准

### 1. Context Agent（上下文构建）

**职责**：构建写作任务书，提供本章上下文

#### 评估标准

| 检查项 | 权重 | 通过标准 | 评估方法 |
|--------|------|----------|----------|
| 大纲加载 | 20% | 正确加载本章大纲 | 检查任务书中是否包含本章情节要点 |
| 角色状态 | 20% | 准确反映当前状态 | 与 character_growth.json 对比 |
| 伏笔提醒 | 20% | 覆盖所有相关伏笔 | 与 foreshadow_tracker.json 对比 |
| 约束完整 | 20% | 包含所有写作约束 | 检查防幻觉三定律落实 |
| 格式规范 | 20% | 五段式结构完整 | 检查任务书格式 |

#### 输出格式要求

```json
{
  "chapter": 51,
  "outline_summary": "本章需完成：主角突破金丹期",
  "character_states": {
    "protagonist": {
      "realm": "筑基巅峰",
      "goal": "突破金丹"
    }
  },
  "pending_foreshadows": [
    "伏笔A：神秘势力出现"
  ],
  "constraints": [
    "不能越级挑战"
  ],
  "writing_guide": "重点描写突破时的异象"
}
```

#### 不合格情况

- 大纲要点遗漏超过 30%
- 角色状态与实际不符
- 未提及重大伏笔
- 格式缺失超过 2 项

---

### 2. Data Agent（数据提取）

**职责**：从正文提取事实，更新状态文件

#### 评估标准

| 检查项 | 权重 | 通过标准 | 评估方法 |
|--------|------|----------|----------|
| 实体提取 | 25% | 提取所有实体 | 与人工标注对比 |
| 状态更新 | 25% | 状态准确 | 与正文对比 |
| 伏笔提取 | 20% | 不遗漏伏笔 | 与正文对比 |
| 摘要质量 | 15% | 概括准确 | 人工审查 |
| 时效性 | 15% | 及时更新 | 检查时间戳 |

#### 输出格式要求

```json
{
  "chapter": 51,
  "entities_extracted": [
    {
      "name": "林逸",
      "type": "character",
      "action": "突破成功"
    }
  ],
  "state_updates": {
    "protagonist": {
      "realm": "金丹期",
      "layer": 1
    }
  },
  "new_foreshadows": [
    "神秘势力开始调查主角"
  ],
  "summary": "主角成功突破到金丹期，但引来了神秘势力的注意"
}
```

#### 不合格情况

- 实体遗漏超过 20%
- 状态更新错误
- 伏笔遗漏
- 摘要与正文不符

---

### 3. Reviewer Agent（质量审查）

**职责**：六维质量审查，检查一致性、连贯性、AI味

#### 评估标准

| 检查项 | 权重 | 通过标准 | 评估方法 |
|--------|------|----------|----------|
| 爽点密度 | 15% | 每章至少1个爽点 | 人工审查 |
| 设定一致 | 20% | 无设定冲突 | 与设定对比 |
| 节奏比例 | 15% | Strand比例合理 | 统计检查 |
| 角色一致 | 20% | OOC<10% | 与人设对比 |
| 叙事连贯 | 15% | 无逻辑断层 | 全文审查 |
| 钩子强度 | 15% | 吸引追读 | 人工评估 |

#### 输出格式要求

```json
{
  "chapter": 51,
  "review_results": {
    "high_point": {
      "score": 85,
      "issues": []
    },
    "consistency": {
      "score": 90,
      "issues": []
    },
    "pacing": {
      "score": 75,
      "issues": ["Fire线断档8章"]
    },
    "ooc": {
      "score": 95,
      "issues": []
    },
    "continuity": {
      "score": 80,
      "issues": []
    },
    "reader_pull": {
      "score": 70,
      "issues": ["钩子不够强"]
    }
  },
  "overall_score": 82,
  "recommendations": [
    "增加感情线描写"
  ]
}
```

#### 不合格情况

- 任何维度得分 < 60
- 设定冲突超过 2 处
- OOC 超过 20%
- 无爽点或钩子

---

### 4. Auto-Validator（自动校验）

**职责**：提交前基础校验

#### 评估标准

| 检查项 | 权重 | 通过标准 |
|--------|------|----------|
| 字数达标 | 30% | 在目标字数±20%范围内 |
| 无明显错误 | 40% | 无事实错误 |
| 格式规范 | 30% | 符合格式要求 |

#### 不合格情况

- 字数偏差超过 50%
- 存在明显事实错误
- 格式严重不规范

---

### 5. Foreshadow Manager（伏笔管理）

**职责**：伏笔埋设、追踪、回收

#### 评估标准

| 检查项 | 权重 | 通过标准 |
|--------|------|----------|
| 伏笔登记 | 30% | 所有伏笔已登记 |
| 回收提醒 | 30% | 到期前提醒 |
| 逻辑合理 | 40% | 伏笔回收有铺垫 |

#### 不合格情况

- 伏笔遗漏登记
- 回收无铺垫
- 伏笔过期未回收

---

### 6. Regression Tester（回归测试）

**职责**：检查新内容与前文的一致性

#### 评估标准

| 检查项 | 权重 | 通过标准 |
|--------|------|----------|
| 设定一致 | 40% | 无设定冲突 |
| 逻辑一致 | 30% | 无逻辑漏洞 |
| 细节一致 | 30% | 数字、名称一致 |

#### 不合格情况

- 与前文设定冲突
- 逻辑矛盾
- 关键细节不一致

---

### 7. Emotion Analyzer（情绪分析）

**职责**：分析章节情绪张力

#### 评估标准

| 检查项 | 权重 | 通过标准 |
|--------|------|----------|
| 情绪曲线 | 40% | 有起伏，不平淡 |
| 情绪类型 | 30% | 与情节匹配 |
| 情绪强度 | 30% | 强度适当 |

#### 不合格情况

- 全章情绪平淡
- 情绪与情节不匹配
- 情绪强度过大或过小

---

### 8. Style Learner（风格学习）

**职责**：学习用户风格偏好

#### 评估标准

| 检查项 | 权重 | 通过标准 |
|--------|------|----------|
| 模式识别 | 40% | 准确识别偏好 |
| 规则生成 | 30% | 规则合理可执行 |
| 持续学习 | 30% | 随修改更新 |

#### 不合格情况

- 模式识别错误
- 规则过于模糊
- 无法指导写作

---

## 评估流程

### 自动化评估

1. **语法检查** - 格式、标点、错别字
2. **规则检查** - 反模式、可读性
3. **一致性检查** - 与设定、历史的对比

### 人工评估

1. **质量审查** - Reviewer Agent
2. **风格评估** - 与风格 DNA 对比
3. **创新性评估** - 情节、人物、语言的创新

### 反馈循环

```
写作完成 → 评估 → 问题记录 → 修改建议 → 重新写作
    ↑                                              ↓
    └────────────── 用户反馈 ←───────────────────┘
```

## 评估记录

每次评估后应记录：

1. 评估时间
2. 评估者（Agent名称）
3. 得分和状态
4. 发现的问题
5. 修改建议

记录存储位置：`.webnovel/evaluations/{chapter}-{timestamp}.json`
