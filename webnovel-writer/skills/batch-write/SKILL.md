# `/batch-write` - 批量写作

## 功能说明

批量写作技能允许用户一次性启动多个章节的连续写作，自动管理队列状态，实现无人值守的连续创作。**所有章节都在项目目录下的 `正文/` 目录内保存。**

## 项目目录检查（第一步，必须执行）

在开始批量写作前，按以下顺序确认项目目录：

1. 查找包含 `.webnovel/state.json` 的目录，或目录名明显是书名
2. 找到项目目录后，在该目录内进行所有写作
3. 找不到项目目录时，提示"尚未初始化小说项目，请先运行 `/webnovel-init`

**规则：永远在项目目录内批量写作。找不到项目目录就不启动。**

## 使用场景

- 一次性写作多章（如第51-60章）
- 需要连续创作时减少人工干预
- 批量处理预写章节
- 无人值守写作模式

## 参数

- `[范围]`：章节范围，格式为 `起始-结束`，如 `51-60`
- `--auto`：自动模式，遇到问题自动处理
- `--stop`：遇到阻断问题立即停止
- `--style [风格]`：指定批量写作的统一风格

## 队列状态机

```
PENDING → WRITING → REVIEW → COMMITTED
   ↓          ↓         ↓         ↓
[启动]    [进行中]  [审查中]  [已完成]
   ↓          ↓         ↓
BLOCKED ← FAILED
```

## 命令列表

| 命令 | 功能 |
|------|------|
| `/batch-write 51-60` | 启动51-60章批量写作 |
| `/batch-status` | 查看队列状态 |
| `/batch-pause` | 暂停队列 |
| `/batch-resume` | 继续队列 |
| `/batch-skip` | 跳过当前章节 |
| `/batch-stop` | 停止队列 |

## 自动衔接机制

### 章节上下文加载

每个章节开始前自动加载：
- 前章摘要和结尾
- 前章钩子
- 实体状态
- 活跃伏笔
- 用户风格配置

### 衔接检查项

| 检查项 | 说明 | 失败处理 |
|--------|------|----------|
| 地点匹配 | 新章节地点与前章一致 | 警告 |
| 时间连续 | 时间线无跳跃 | 添加过渡句 |
| 钩子回应 | 前章钩子得到回应 | 暂停 |
| 情绪流畅 | 情绪过渡自然 | 添加过渡段 |

## 问题处理流程

### 阻断问题（如剧情冲突）

1. 暂停队列
2. 记录问题详情
3. 等待用户决策（修复/跳过/解决后继续）

### 非阻断问题（如AI味警告）

1. 记录警告
2. auto模式下继续，manual模式暂停
3. 汇总到章节审查报告

## 队列配置文件

存储位置：`.webnovel/queue_state.json`

```json
{
  "version": "1.0",
  "queue_id": "queue-20240115-1030",
  "config": {
    "start_chapter": 51,
    "end_chapter": 60,
    "auto_continue": true,
    "stop_on_blocking": true
  },
  "progress": {
    "current_chapter": 54,
    "completed": 3,
    "total": 10
  }
}
```

## 最佳实践

### 推荐配置

```bash
# 标准批量写作
/batch-write 51-60

# 自动模式（问题自动处理）
/batch-write 51-60 --auto

# 严格模式（遇错即停）
/batch-write 51-60 --stop
```

### 批量写作前检查清单

1. ✅ 大纲已完善
2. ✅ 章节衔接逻辑清晰
3. ✅ 角色状态已更新
4. ✅ 伏笔埋设计划已确认

## 输出文件

- 章节文件：`正文/第{章号}章-{标题}.md`
- 队列状态：`.webnovel/queue_state.json`
- 审查报告：`审查报告/batch-{queue_id}.md`

## 注意事项

- 批量写作过程中可随时暂停或停止
- 支持中断恢复，队列状态自动保存
- 建议每次批量不超过20章
- 批量写作完成后建议进行一次整体审查
